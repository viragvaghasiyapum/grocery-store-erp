This matrix explains current behavior and maps replacement paths from the [revised implementation plan](../../revised-implementation-plan.md); that plan governs if wording differs. `dependency-inventory.md` is the reproducible line-level inventory for the desktop app, ScaleAudit, DataGen, tests, SQL and maintenance code. ## Cutover boundaries

### Dependency owners to change together

- **Schema/triggers/views:** `grocery_erp_schema.sql` defines `trg_move_*`, `trg_lot_no_negative`, `trg_sale_*`, `v_product_stock`, `v_expiry_alert`, `v_pnl_entry`, and `v_lot_cache_mismatch`. Shipped migrations 012/015/024 maintain product stock and value projections; 016/018/019/025/026 maintain P/L, dashboard and sale-day projections. Migration 027 adds money-out corrections and 028 adds partial purchase snapshots. All historical scripts are read-only. The generated inventory lists each direct reference and line.
- **Writers:** `StockLedger`, `InventoryService`, `PurchasingService`, `SalesService`, `MoneyOutService`, `CatalogService`, importers and their `OperationGuard` calls; every stock-producing or consuming operation must change in the same cutover. `DataGen` writes fixture SQL directly and `ScaleAudit` calls production services plus SQL probes, so both must migrate before accepting new-schema results.
- **Readers/UI:** Products, Product Stock, Stock, Purchases, Billing, Sales History, Money Out, Assets and Reports pages/windows; `CatalogService` search/stock, Inventory list/FEFO/count, Purchasing invoice/vendor balance, Sales history/returns, Money Out expiry/damage, `ReportService`, `ReportDefinitions`, `ReportOutputService` and exports. Page navigation and localization resources need a packaged-app check after screen removal.
- **Startup/recovery:** `MigrationRunner`'s newer-schema guard and projection rebuilds, `MaintenanceService` startup/lot-cache verification, `BackupService` verify/restore barrier, and `ScaleAudit verify` must switch from ledger parity to source-document arithmetic. Old binaries already fail on a newer `user_version`; keep that refusal in tests and release instructions.
- **Tests:** Integration Sales, StockIn, Catalog, MoneyOut, Reports and Foundations; UI PhaseZeroSmoke, ModuleComposition, ScaleUi and PackagedOperatorJourney; architecture tests and ScaleAudit/DataGen fixture checks. The generated appendix enumerates their textual references and status/expiry usages.

No schema-28 write path may mix ledger-trigger and direct quantity changes. Phase 1 adds historical snapshots while preserving current stock behavior. Phase 2 builds direct operations on an isolated fixture. Phases 3–5 migrate business callers. One verified cutover switches every stock writer, projection and startup/recovery check; only then can a later migration drop movement tables and screens. Old binaries already reject a database whose `user_version` exceeds `MigrationRunner.LatestVersion`; the first upgraded schema must be 29 or higher and the installer must enforce this guard.

## Table and form UI acceptance for later phases

At 1366×768, a list page has one compact title/action line, a single-line search and primary filters, an optional collapsed advanced-filter region, a grid taking the remaining height, and a fixed pagination/status line. Bulk actions appear only with a selection, with a visible selected count and review before posting. Tabs have short labels and do not nest page-level vertical scroll around a DataGrid. Forms group relevant fields, hide fields inapplicable to the selected line type, show errors beside fields plus a summary, and keep the main commit action visible. Search/filter calls are cancellable and bounded; virtualized grids retain only a page of DTOs. English/Gujarati labels, keyboard order and 125%/150% scaling must pass visual and automation review. These are Phase 7 implementation gates; Phase 0 does not remove live controls.
