# Phase 5 performance work — 14 October 2026

This records the Phase 5 software changes and checks available on VARK (24 logical processors, .NET 10.0.12, SQLite 3.53.3). The disposable store used for output and printing held 5,189,871 sale lines, 5,413,052 stock movements, 222,500 lots, and 47,000 products at schema 24. It was relocated from a 3,155,263,273-byte source tree, including its backups. These are local measurements; no physical store peripherals were connected.

## Changes

- Label jobs split into at most 25 rows and 100 copies, with a 256 KiB limit for both rendered TSPL and serialized journal payload. All chunks are saved before the first send. A failed batch leaves unsent chunks in review, and startup converts interrupted pending/sending chunks to review. Receipts and cash drawer work use a bounded priority channel; labels and day-end use an eight-job background channel. The worker checks priority after each chunk. Printer-spooler acceptance remains a distinct physical event.
- Excel export builds off the WPF UI thread, reports rows processed, checks cancellation during construction, writes to a temporary workbook, and replaces the target only after a successful save. A4 construction and XPS serialization run on a separate STA thread; the themed `DocumentViewer` opens on the main UI thread so WPF resources are not used across threads. The temporary XPS file is released on close. Preview caps at 100 rows, labels the cap in the document and page, and points users to the existing full CSV export.
- Relocation preserves a recognized `.moving` staging tree after failure. Existing staged files are reused only if size and SHA-256 match; replacements are copied to `.partial` files and atomically renamed. Each new copy checks available space with a 64 MiB reserve and reports `DiskFull` before copying if insufficient. Every source file is hashed against the staged copy before SQLite quick-check and foreign-key validation. The source is retained until the bootstrap switch completes.

## Acceptance still open

- Measure receipt start p50/p95/p99 with a real receipt printer, drawer and day-end output while a label batch is active, including printer-offline and retry scenarios. The software queue cannot prove a `<1 s` physical start.
- Print and inspect 58/80 mm receipts, label templates, Gujarati raster output, cutter/drawer behavior, and populated A4 reports on the intended hardware. Verify a physical scanner and its `<50 ms` scan-to-line target.
- On the actual deployment storage, confirm low-space behavior and power-loss durability. The software fault test injected a zero-space reading; filling this shared workstation volume was not used as a test. The updater kill was during extraction, before the current-directory swap; a physical power cut at the swap boundary remains a separate release check.
- Complete native Gujarati review, second-PC restore, 125%/150% display scaling on the intended screen, and pilot sign-offs from the Phase 5 checklist.

The repository-wide `dotnet format --verify-no-changes` gate remains open because it reports pre-existing whitespace, line-ending and import-order issues across unrelated files. The files changed for this phase pass the targeted whitespace check.
